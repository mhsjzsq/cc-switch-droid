# CC Switch Droid Hook

独立启动版，版本 `2.2.4`。以 `CC-Switch-Droid-Addon` 的 Droid 界面、额度查询和用量同步为基础，参考本机 `Codex-Hook` 的启动与 Hook 生命周期方式重新组织。

从本目录的 **Open-Hook.cmd** 启动原版 CC Switch，并为这一次启动加载 Droid 功能。原版可执行文件保持原样；本目录自带 Python，不依赖原插件目录或系统 Python。

## 使用

1. 从托盘完整退出已运行的 CC Switch。只关闭窗口可能仍会保留托盘进程。
2. 如果旧版 Droid Addon 助手仍在运行，先停止它并停用它的开机启动项。新入口会检测冲突并提示，不会结束旧进程。
3. 双击 `Open-Hook.cmd`。没有 `config.json` 时会打开首次配置窗口：选择包含 `cc-switch.exe` 的目录（也可粘贴完整 EXE 路径），填写 Droid / Factory API Key，点击“保存并启动”。两项均需填写，Key 默认隐藏，可勾选“显示 API Key”。
4. 入口自动生成配置并继续启动原版，无需再次双击。已有配置时直接按原配置启动；等待 Droid Hook 加载成功后启动脚本退出，原版窗口继续运行。
5. 在侧栏打开 Droid 页面，查看额度和本地用量。用量页继续提供 Droid 筛选。

本地这一份已填入原版路径：

```text
E:\App\Protable\CC-Switch-v3.20.4-Windows-Portable\cc-switch.exe
```

2026-10-21 读取本机 EXE 版本信息和原版启动日志，实际版本为 **4.0.12**。上面的目录名没有随更新改变，不能据此判断原版版本。

更新 Hook 源码后，需要从托盘完整退出当前 CC Switch，再运行本目录 `Open-Hook.cmd`。会话助手在启动时读取界面脚本，已运行的旧助手不会自动加载磁盘上的新代码。

`2.2.3` 将用量统计页上方的长段说明移入左侧 Droid 页的“统计说明”折叠卡片，按记录、日期、费用、速度分项展示，默认收起；额度或用量刷新时保持当前展开状态。统计和筛选逻辑不变。

已有的 Factory key、额度刷新间隔和数据路径已复制到本地 `config.json`。配置与原插件之后各自独立。`config.json` 含个人信息，已加入 `.gitignore`；分享本项目时请只提供 `config.example.json`，不要打包个人配置和 `data`。

首次配置会使用 `config.example.json` 的默认项，将选择的 EXE 路径和输入的 Key 保存为本目录的 `config.json`。JSON 转义由程序处理，窗口中可以直接粘贴普通 Windows 路径。文件完整写入同目录临时文件后再改名，保存过程不会覆盖已有配置。Key 以明文保存在本地配置中；输入框隐藏只影响显示。配置窗口只检查路径与输入格式，Key 的账户权限或有效性由启动后的额度查询反馈。

首次配置仅在文件不存在时出现；将包含个人 `config.json` 的整个目录复制到另一台电脑，不会自动重新配置。需要手动修改已有配置时，路径中的反斜杠按 JSON 规则写成 `\\`，也可以使用 `/`。命令行使用 `launch-hook.ps1 -NoMessageBox` 时不显示配置窗口，缺少配置只返回错误。

需要桌面入口时，可以手动为 `Open-Hook.cmd` 创建快捷方式。本版本没有安装程序，不注册开机启动项。

## 与旧版的区别

```text
Open-Hook.cmd
  └─ launch-hook.ps1：短期启动协调与错误提示
      └─ pythonw.exe + addon/hook_client.py：本次会话的助手
          ├─ 启动原版 cc-switch.exe
          ├─ 只连接该进程的 WebView2 页面，注入 Droid 界面
          └─ 在这个会话内执行用量同步与额度查询
```

和参考项目一样，运行时仍有一个随应用会话存活的助手进程，用来维持页面 Hook 与处理本地文件、数据库和网络请求。它只服务自己启动的原版进程，不会等待、接管以后从普通图标启动的程序。

原版完整退出后，助手取消后续任务；未提交的同步事务会在取消检查点回滚，已发出的网络请求会等待响应或其超时后收尾，随后助手退出。若只是将 CC Switch 关闭到托盘，则仍属于同一次运行会话。

启动时动态选择本机回环端口，通过原版子进程的 `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS` 环境变量启用调试。连接前检查端口监听进程是否属于本次启动的 CC Switch，页面也只接受 Tauri 应用地址。这里不会改写用户或系统环境变量、WebView2 注册表策略、原版 EXE 或浏览器资料目录。

界面脚本通过 `Page.addScriptToEvaluateOnNewDocument` 登记，并立即注入当前页面；同一会话中发生页面重载时可以再次加载并重新收到数据。设置页面等正常导航不会仅因 Droid 侧栏按钮暂时消失而被判定为连接中断。

## 从旧版切换

新旧助手共用互斥标记，避免两个版本同时控制页面或写入同一数据库。新入口不会自动停止旧版，也不会自动改动旧目录。

可以选择以下方式处理旧版：

- 临时停用：在任务管理器的详细信息中显示“命令行”列，准确找到包含旧目录 `addon\main.py` 的 `pythonw.exe` 后结束该助手。不要结束其他 Python 程序。在 `shell:startup` 中移走旧版的 `CC Switch Droid Addon.lnk`，可以保留到其他目录以便恢复。
- 正式卸载：自行运行旧目录的 `uninstall.cmd`。若希望延续历史记录，在“删除已导入的 Droid 用量记录”问题上选择 **N**。该方式会执行旧版卸载流程，因此本项目不会代为运行。

如果旧插件还留有 WebView2 调试端口策略，新入口会报告冲突，需要先撤销旧策略。旧版有策略备份时可以使用其卸载流程恢复；没有备份时，不建议直接删除整个 WebView2 策略项，应先检查具体值。新项目不会覆盖外部管理的参数。

已有数据库中的 Droid 记录继续保留。同步以该数据库里的实际累计导入量作为依据，不依赖旧目录的 `data/sync_state.json`，因此不用复制旧进度文件。

## 配置

| 字段 | 用途 |
| --- | --- |
| `ccSwitchExecutable` | 原版 `cc-switch.exe` 路径。留空时尝试 PATH 和当前用户的常见安装目录；便携版建议明确填写。 |
| `ccSwitchArguments` | 传给原版的额外参数数组，默认 `[]`。调试端口和用户资料目录参数由入口限制。 |
| `factoryApiKey` | Factory API key，首次配置窗口要求填写。已有配置中手动留空时，仍依次读取启动环境的 `FACTORY_API_KEY` 和 `~/.factory/.env`；均未配置只影响额度查询。 |
| `quotaRefreshSeconds` | 正常额度刷新间隔，整数，15–86400 秒。查询失败会延长自动重试间隔并标记旧结果。 |
| `ccSwitchDbPath` | CC Switch 数据库文件。留空使用 `~/.cc-switch/cc-switch.db`。路径错误时不创建空数据库。 |
| `droidSessionsDir` | Droid 会话目录。留空使用 `~/.factory/sessions`。 |
| `droidLogsDir` | Droid 本地运行日志目录，用于速度和首 Token 时间。留空使用所选会话目录旁的 `logs`，通常是 `~/.factory/logs`。旧配置无需增加此字段即可使用默认路径。 |
| `startupTimeoutSeconds` | 等待初次 Hook 加载的上限，整数，10–120 秒，默认 45 秒。 |

路径支持 `~` 和 `%变量名%`；相对路径以本项目目录为基准。使用了 CC Switch 自定义数据目录时，需要明确配置其数据库路径。

Factory key、额度间隔和数据路径约每 10 秒重新读取一次；格式错误会提示并继续使用上次有效配置。已经开始的任务使用它启动时的配置完成，旧路径或旧 key 的结果不会显示到新配置下。原版路径、启动参数和启动超时需要下次从入口启动才生效。

用量同步间隔读取所选数据库旁边的 `settings.json` 中的 `usageDashboardRefreshIntervalMs`；缺失或无效时使用 60 秒，最短 2 秒。原版“立即同步”按钮会同时请求一次 Droid 同步。Droid 页的“立即刷新”用于额度查询。

## 同步与统计口径

- 累计 Token 以 `proxy_request_logs` 中实际已导入的 Droid 记录对账；增量、采样快照和归属信息在同一个 SQLite 事务中提交。
- 读取会话文件时检查其是否正在变化；累计字段不完整、重复会话 ID、累计值倒退等情况会跳过或提示，不擅自删除历史记录。
- 第一批导入、跨日变化、缺少可信采样边界的补录统一标记为“日期未分配”。Droid 页的“今日用量”只统计前后采样都落在当天的增量。
- 多模型会话不会把全部 Token 归给最后一个模型。仅在模型证据完整且数据库中存在精确匹配价格时估算成本，其余显示“未知”及已知费用部分。
- 旧版记录原样保留，并提示日期、费用和估算速度未经核实。旧记录中的错误不会因为更换启动方式就自动消失。
- Factory 查询失败时保留最近一次成功数据并明确显示“旧额度”和错误，最后成功时间不会伪装成这次失败时间。

这里的记录是会话累计计数的增量，不是逐请求账单，不能直接作为请求次数。只有能对应到完整单次请求的记录才补全耗时。原版统计页暂时不了解插件的归属元数据：未知费用的 `0` 只是数据库占位值，日期未分配记录的时间是导入时间。相关说明集中在左侧 Droid 页的“统计说明”中，不再插入原版统计页顶部；判断今日用量请以 Droid 页展示的口径为准。

当前同步读取会话设置中的累计用量，并读取会话 JSONL 判断模型归属；不会把对话正文导入 CC Switch 原生“会话”页面。一条增量可能覆盖多次助手回复，不能据此还原每条回复的文本、时间或速度。

### 原生速度列与首 Token 时间

同步时读取 `droid-log-single.log` 和它的轮换文件，使用 Droid 自己记录的 `chat_client_time_to_first_token`、`chat_client_request_duration`、成功消息 ID 和最终流式用量。只接受完整的事件顺序，并核对同一进程、会话、trace/span 与请求起止时间；同一 span 的下一次请求会重新开始配对。

只有导入行的会话 ID、输入/输出/缓存读取/缓存写入四类 Token 与某一条请求完全一致，且已知模型一致时，才进一步考虑匹配。`2.2.1` 起保存新增量的采样起止时间：有可信起点时，请求必须在该采样区间内完成；历史记录或没有可信起点的首次导入仍限于导入时间前 120 秒（允许秒级存储带来的不足一秒舍入差）。如果累计计数延迟落盘导致请求不在区间内，速度保持未知。

多个候选请求或多条导入行争用同一个请求证据时均跳过；已使用的请求证据也参与歧义判断，防止排除它后把其他请求误当成唯一候选。不会覆盖原本已有的耗时，也不会拆分累计 Token。

匹配成功后，在同一同步事务中填写原版字段：`latency_ms` 为请求总耗时、`first_token_ms` 为首 Token 耗时、`duration_ms` 为两者之差。当前原版 4.0.12 将 `data_source='droid_session'` 归入会话日志，因此速度显示为 `≈ 输出 Token / 请求总秒数`，包含首字等待，要求输出至少 200 Token、总耗时至少 1 秒；即使填写了 `duration_ms`，该分支也不扣除首字。首字列使用 `first_token_ms`，同样带 `≈`。原版本地路由请求另用扣除首字的生成时间计算速度，不能混为同一口径。参见[原版 4.0.12 格式化代码](https://github.com/farion1231/cc-switch/blob/v4.0.12/src/components/usage/format.ts)。Hook 不发送额外测速请求。

耗时未知的已导入记录也会尝试补全，Token、费用和时间不会改变。多请求汇总、日志缺失、重试或供应商轮换、无法唯一对应等情况继续保留未知值，显示 `—`。新补全逻辑不会把轮询间隔、用户思考或工具执行时间当作模型生成时间。匹配证据保存在数据库的 `droid_hook_timings` 表，日志正文和凭据不会复制进去。

旧版脚本曾按相邻消息的时间差估算耗时，这些已有值仍保留，满足当前原版显示条件时仍会显示，不能视为新的逐请求指标。能补全耗时不代表一定显示速度：短回复也可能因原版的输出或时间门槛显示 `—`。速度仍受日志计时与流式分块影响，不是独立测速结果，Hook 没有人为限幅或伪造缺失值。

会话运行时会在所配置的 CC Switch 数据库中使用 `droid_addon_snapshots`、`droid_addon_records` 和 `droid_hook_timings` 三张辅助表，以及 `data_source='droid_session'` 的导入记录。`2.2.1` 会在下一次正常同步事务中为记录元数据添加 `sample_start`、`sample_end` 两列，无需手动迁移；旧记录缺失的采样边界保持为空。这些数据属于持久化用量记录，与入口日志分开保存。

## 原版设置保护

`2.2.2` 在确认原版已退出、启动新进程之前，读取当前用户的 `~/.cc-switch/settings.json`，将原始内容独立保存到 `data/settings-backups`。该路径来自原版 4.0.12 的设备设置位置，与 Hook 配置的用量数据库位置分开。首次安装没有设置文件时正常继续；已有文件无法读取，或含无效 JSON、重复字段、非标准数值等情况时停止本次启动，保留原文件和可读取的损坏副本，不让原版带着坏 JSON 启动后回退默认值。

此保护不会写入、修复或自动恢复原版设置，也没有拦截原版运行中的设置保存；JSON 检查不等于完整的原版字段类型校验。副本可能含账号或同步配置，属于私人数据，不应随项目分享。数据库备份不能代替设备设置文件备份。

本机 2026-10-21 16:01:18（Asia/Taipei）的原版日志明确报告 `settings.json` 第 62 行第 2 列有多余内容，随后使用默认设置。当前文件已在 16:02:35 重新保存，本次未找到该文件在损坏前的完整备份，也未自动回滚数据库或猜测旧开关。原版 4.0.12 的设置源码存在直接覆盖写入、部分保存路径在写文件后才加锁的并发风险；这与日志相容，但尚不能证明是此次损坏的原因。根治该风险需要原版串行保存并使用原子替换，本 Hook 的启动保护不能代替原版修复。

## 停用和移除

1. 从托盘完整退出本次 CC Switch，等待助手结束正在收尾的任务；如果出现错误提示，关闭提示框。
2. 之后直接打开原版 `cc-switch.exe`，本项目不会随普通入口启动。
3. 不再需要时，删除自己创建的快捷方式和本项目目录即可。本版本没有需要卸载的开机启动项或注册表策略。

删除项目目录会同时删除这里的个人配置与诊断日志，请按需先保存。已经导入原版数据库的用量和辅助表会保留，停用 Hook 不会删除历史数据。普通入口仍可能显示原生统计中的既有 Droid 记录，但不会加载本项目的 Droid 页面。旧版 Addon 若仍保持运行，其行为需要单独停用。

## 状态和故障信息

| 文件 | 内容 |
| --- | --- |
| `data/status.json` | 最近一次取得会话互斥标记的运行状态与进程 ID。 |
| `data/launches/<启动ID>.json` | 本次启动的独立状态，入口同时校验启动 ID 和助手 PID，避免读取旧状态误判成功。 |
| `data/hook.log` | 启动、连接、同步和错误日志。约 1 MB 后轮换为 `hook.previous.log`。 |
| `data/settings-backups/` | 每次通过 2.2.2 入口启动前保存的原版设备设置副本；不自动恢复。 |

状态包括 `starting`、`attached`、`reconnecting`、`stopping`、`stopped` 和 `error`。日志不记录 API key 或完整会话内容。

启动失败会提示原因；初次加载成功后若连接持续中断超过 15 秒，会结束本次 Hook 并弹出错误提示。原版窗口保留，不会被强制关闭或重启。此时要重新加载，请先完整退出原版再打开本入口。调试端口随原版进程退出而结束，不能只靠退出助手关闭原版已经打开的端口。

本次界面静态复查对照本机实际运行的 CC Switch 4.0.12。原版升级后若改动了 Tauri 页面地址、侧栏结构或用量数据库字段，需要同步调整适配代码；本项目不会静默修改原版以绕过不兼容问题。请以 EXE 版本信息或原版日志为准，便携版目录名可能保留旧版本号。

直接筛选还依赖原版 React 组件的属性结构。适配读取当前已提交的组件树，不修改 Fiber、Hook 链或原版组件；原版升级后若改变该结构，需要更新 `native_usage.js`。适配范围限制在供应商按钮与筛选工具栏之间，不查找或调用页面其他控件的回调。
